Ты начинаешь рабочую сессию по проекту лендинга **TIM**.

## Шаг 1 — Прочитать источники правды

Прочитай **полностью**, без пропусков и без частичного чтения:

1. @TZ_TIM_landing_RU.md — техническое задание. Это закон. Ничего, что ему противоречит, делать нельзя.
2. @ROADMAP.md — план работ, зафиксированные решения, блокеры, журнал задач.

Затем проверь фактическое состояние кода: `git status`, `git log --oneline -10`, структура проекта.
Если ROADMAP расходится с реальностью — верь коду и сразу поправь ROADMAP.

## Шаг 2 — Доложить статус

Кратко, на русском, без воды:

- **Текущий этап** и процент готовности по этапам
- **Что сделано** с прошлой сессии (по git-логу)
- **Что следующее** — 2–3 ближайшие задачи из ROADMAP
- **Блокеры** — что ждём от заказчика и что именно они держат

## Шаг 3 — Рабочий режим (действует до `/stop`)

С этого момента и до команды `/stop` соблюдай следующий порядок **при каждой поставленной задаче**:

1. **Сначала ROADMAP, потом код.** Получил задачу — сперва внеси её в `ROADMAP.md`:
   - строка в раздел «Журнал задач» (номер, дата, формулировка, этап, статус «В работе»);
   - если задача не укладывается в существующие пункты — добавь новый пункт в нужный этап;
   - если задача меняет ранее принятое решение — запиши это в «Журнал решений» с обоснованием.
2. **Проверь на соответствие ТЗ.** Если задача противоречит ТЗ — скажи об этом одной-двумя фразами, предложи вариант в рамках ТЗ и жди решения заказчика. Если заказчик подтвердил — выполняй и зафиксируй отступление в «Журнале решений».
3. **Выполни задачу целиком.** Не сужай объём молча.
4. **Обнови статусы** в ROADMAP: `[~]` → `[x]`, снятые блокеры, поле «Обновлён» вверху файла.

Ничего не коммить по ходу работы — коммит делается один раз, по команде `/stop`.

## Шаг 4 — Ждать

Не начинай писать код по своей инициативе. Доложи статус и жди задачу от заказчика.
Исключение: если аргументом команды передана задача — обработай её по порядку из Шага 3.

Аргументы команды (если пусто — просто доложи статус): $ARGUMENTS
