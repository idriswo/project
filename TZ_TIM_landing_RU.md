# Техническое задание (ТЗ)
## Лендинг-пейдж SaaS-платформы "TIM" (система управления бизнесом)

> **Правка от 2026-07-31 (решение заказчика).** Из текста сайта, кода и любых
> описаний продукта полностью исключены названия конкурентов и сравнения с ними.
> Сайт рассказывает только о собственной системе: склад, касса, бухгалтерия,
> сотрудники. Пункты 1 и 3 ниже приведены в соответствие с этим требованием.

---

## 1. Общее описание проекта

**Название:** TIM
**Тип сайта:** Лендинг-презентация (B2B SaaS)
**Основная цель:** Привлечь владельцев бизнеса (магазины, рестораны, компании) — познакомить с системой, показать тарифы и получить регистрацию (лидогенерация).
**Стек:** Next.js (App Router), TypeScript, Tailwind CSS, Markdown/MDX (без CMS), Vercel

Сайт **не продаёт физический товар**, а продаёт подписку на сервис (SaaS). Поэтому акцент должен быть на доверии (trust), чёткости ценностного предложения (value proposition) и CTA на регистрацию — а не на "корзину" покупок.

## 2. Основной технический стек

| Компонент | Выбор | Причина |
|---|---|---|
| Framework | Next.js 15, App Router | RSC → лучший SEO, высокая скорость |
| Язык | TypeScript | Меньше ошибок, поддержка в долгосрочной перспективе |
| Стили | Tailwind CSS | Скорость разработки, консистентность |
| Контент | Markdown/MDX в `content/` (без CMS) | Простота, без дополнительных затрат |
| Rendering | **SSG (Static Site Generation)** | Контент меняется редко → статический HTML = максимальная скорость и лучший SEO |
| Хостинг | Vercel | Edge CDN, нативная интеграция с Next.js |
| Форма | Server Action / API Route + email (Resend) или интеграция с CRM | Приём лидов |
| Аналитика | Yandex Metrica + Google Analytics 4 | Учитывая региональную аудиторию (РФ/Центральная Азия) |

> **Рекомендация:** Markdown лучше обрабатывать не через `next-mdx-remote` в runtime, а через `contentlayer2` либо чтение файлов на этапе `generateStaticParams`/build-time — это повышает SEO и скорость, так как всё превращается в HTML заранее, при сборке.

## 3. Структура страницы (Page Structure)

```
1. Header (sticky) — Логотип, Навигация (Отрасли, Как это работает, Тарифы), CTA "Регистрация"
2. Hero — Главный заголовок (H1), краткое описание, 2 CTA (Получить демо / Регистрация), скриншот/макет системы
3. Features block — "Возможности" — что умеет система: склад, касса, бухгалтерия, сотрудники (без сравнений с конкурентами)
4. Industries block — Карточки отраслей (Одежда, Продукты питания, Рестораны...) с иконками
5. How it works — 3-4 шага с нумерацией
6. Pricing — Таблица тарифов (карточка за карточкой), CTA в каждом тарифе
7. (Рекомендуется) Testimonials/Trust — Логотипы клиентов или отзывы (повышает доверие и конверсию)
8. (Рекомендуется) FAQ — Важно для SEO (long-tail запросы) и снижения сомнений перед регистрацией
9. Footer — Ссылки, контакты, авторские права, соцсети
```

## 4. Требования по SEO (детально)

### 4.1. Metadata & On-page
- Использование Next.js `generateMetadata()` на каждой странице — `title`, `description` (150–160 символов), `canonical`
- Один `<h1>` на странице (в блоке Hero), логичная иерархия H2/H3 в остальных блоках
- Open Graph + Twitter Card теги (`og:title`, `og:image`, `og:description`) для корректного отображения при шеринге в соцсетях
- Чистые URL, без параметров (например `/pricing`, а не `/page?id=2`)

### 4.2. Structured Data (JSON-LD)
Добавить следующие схемы для rich snippets в Google:
- `Organization` — данные о компании
- `SoftwareApplication` или `Product` — для системы TIM с ценами
- `FAQPage` — если есть блок FAQ (повышает CTR в поисковой выдаче)
- `BreadcrumbList` — если появятся внутренние страницы

### 4.3. Технические аспекты
- `app/sitemap.ts` — динамический sitemap.xml
- `app/robots.ts` — robots.txt с разрешением индексации
- `next/image` с форматами WebP/AVIF, `priority` для изображения в Hero, `alt` для каждого изображения
- `next/font` для шрифтов (без layout shift, без внешних запросов в runtime)
- Целевые показатели Core Web Vitals: **LCP < 2.5s**, **CLS < 0.1**, **INP < 200ms**
- Lighthouse score: 90+ по Performance, SEO, Accessibility, Best Practices
- Mobile-first, все блоки должны корректно работать от 320px до 1920px

### 4.4. Язык/регион
- Если сайт будет только на русском — `lang="ru"` в `<html>`
- Если в будущем планируются таджикский/английский языки — рекомендуется уже сейчас заложить структуру `/[locale]/` в App Router (например, через `next-intl`), чтобы не переделывать архитектуру позже

## 5. Форма и интеграции
- Форма (Демо/Регистрация): имя, телефон/почта, название бизнеса, отрасль (dropdown)
- Защита от спама: honeypot-поле или Cloudflare Turnstile (без тяжёлой reCAPTCHA, которая может ухудшить UX)
- Результат формы → email (через Resend/SendGrid) и/или интеграция с CRM (если имеется)
- Валидация на клиенте (Zod + react-hook-form) и повторная проверка на server action

---

## 6. Нефункциональные требования
- HTTPS (автоматически на Vercel)
- Переменные окружения (`.env`) для ключей email/аналитики — никогда не в коде, только в git-игноре
- Кастомный домен, подключённый к Vercel
- Backup: поскольку контент в Markdown, сам Git-репозиторий уже является резервной копией

---

## 7. Контент, который нужен от заказчика
- Тексты по каждому блоку (Hero, Возможности, Industries, How it works, Pricing)

- Изображения/скриншоты системы
- Точный список тарифов и цен
