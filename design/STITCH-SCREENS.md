**Дизайн-система:** `design/DESIGN-SPEC.md` + токены `app/globals.css` (`--color-app-*`).

> Макеты Stitch — это **направление**, а не пиксель-в-пиксель. Цвета, шрифты,
> радиусы и отступы берём из нашей дизайн-системы, а не из PNG: в макетах
> встречаются чужая валюта (₽, RUB), чужие подписи («IBM Plex Mono» как текст,
> «Активация Windows»), английские заголовки вперемешку с русскими и разные
> варианты сайдбара. Всё это — артефакты генератора, повторять их не нужно.

## 1. Единые правила для всех новых экранов

1. Все рабочие экраны живут внутри `components/app/app-shell.tsx` (тёмный столб
   навигации `--color-app-navy`, светлая рабочая область `--color-app-bg`).
   В макетах сайдбар нарисован по-разному — **берём наш**, макетный игнорируем.
2. Валюта — **сомонӣ (TJS)**, формат через `lib/format.ts`. Никаких ₽/RUB/$.
3. Числа — `font-mono` + утилита `.num` (см. `globals.css`). Подпись «IBM Plex
   Mono» в макетах — это не текст интерфейса, а пометка генератора.
4. Один янтарный CTA на экран, остальное — сапфир или нейтраль.
5. Каждый экран: строки в `messages/{ru,tg,en}.json`, ни одной строки в JSX.
6. Доступ по ролям — `lib/roles.ts`. Экраны согласований и финансов кассиру
   не показываются.
7. Пока нет эндпоинта — данные из `lib/mock/*`, каждый вызов помечен
   `// MOCK: <метод> <путь>` и вынесен в `lib/api/<домен>.ts`, чтобы замена
   на реальный запрос была правкой одной функции.

## 2. Реестр экранов

Порядок = порядок реализации. Приоритет: сначала то, что закрывает дыры в
ежедневной работе магазина (смена, приёмка, списание), потом печать, потом
маркетинг.

### Волна A — товар и печать

#### Э-01. Модалка «Добавить товар» (`add_product_modal_1`, `add_product_modal_2`)

**Где:** `/inventory/new` — доработка существующей формы.
**Блоки:** Основные сведения (название, категория, артикул/SKU) · Цены
(закупочная, розничная, **маржа % — только чтение, считается сама**) ·
Варианты и остатки (таблица размер → количество → штрихкод) · тумблер
«Распечатать штрихкод после сохранения» (вариант 2) · Отмена / Сохранить.
**Данные:** `POST /inventory/products`, `POST /inventory/products/:id/variants`,
`GET /inventory/categories`. **Всё есть.**
**Новое:** поле `barcode` у варианта — проверить, есть ли в схеме Prisma.

#### Э-02. Предпросмотр этикетки (`barcode_label_preview_1/2/3`, `discount_price_label_variant`)

**Где:** `/labels` (открывается из карточки товара и после приёмки).
**Слева:** сама этикетка — логотип TIM, название, размер крупно, цена,
штрихкод и/или QR. **Справа:** тип принтера (Zebra / Xprinter), тумблеры
«QR-код» и «Штрихкод», размер этикетки (58×40 мм и др.), количество ±, «Печать».
**Режим скидки** (`discount_price_label_variant`): бейдж «СКИДКА», старая цена
зачёркнута, новая — крупно красным (`--color-app-out`), поля «Старая цена» /
«Новая цена».
**Данные:** генерация штрихкода/QR — на клиенте (`bwip-js` или свой SVG),
без бекенда. Печать — `window.print()` + CSS `@page` под размер этикетки.
**Бекенд нужен только для очереди** — см. Э-03.

#### Э-03. Очередь печати (`print_queue_status_screen`)

**Где:** `/labels/queue`.
**Верх:** 3 карточки — активных заданий, напечатано сегодня, статус принтера
(зелёная точка + модель). **Таблица:** Job ID · товар · тип этикетки
(Стандарт/Скидка) · количество · прогресс-бар % · пауза/отмена.
Кнопка «Очистить очередь» (янтарная).
**Данные:** ❌ эндпоинтов нет — см. раздел 3, блок «Печать».

#### Э-04. Настройка сканера (`scanner_configuration_settings`)

**Где:** `/settings/scanner`.
**Блоки:** карточка подключённого устройства + статус · «Зона тестирования»

**Данные:** ✅ бекенд не нужен — настройки в `localStorage`. Сканер работает
