### Найдено и исправлено при проверке контраста

- [x] 12.8 **Текст на янтарных кнопках.** Было `text-ink`, который в тёмной теме становится почти белым: контраст на янтарном падал примерно до 1.9:1. Введён `--color-on-accent`, он не меняется между темами. Затронуты кнопки, бейдж «Популярный», номер третьего шага, кнопка на странице входа
- [x] 12.9 То же в `::selection` — цвет выделенного текста
- [x] 12.10 **`--color-subtle` в светлой теме.** В макете `#7a8296` — это 3.85:1 на белом, ниже порога WCAG AA (4.5:1), а ТЗ п. 4.3 требует Accessibility ≥ 90. Затемнён до `#6b7285`: 4.80:1 на белом, 4.59:1 на подложке. **Это отступление от макета, сделанное ради требования ТЗ**

Все девять проверенных пар проходят AA (≥ 4.5:1) в обеих темах.
Минимумы: светлая — 4.59 (`subtle` на подложке), тёмная — 4.70 (белый на `brand-600`).

## Этап 14 — Возврат с входа и способы входа

- [x] 14.1 Инлайновый `<script>` с темой переведён на `next/script` со `strategy="beforeInteractive"`. Скрипт по-прежнему стоит в HTML до контента, вспышки светлой темы нет

  > **Уточнение от 2026-07-31.** Формулировка «ошибка исправлена» была неверной.
  > Предупреждение `Encountered a script tag while rendering React component`
  > никуда не делось: оно возникает не при первой загрузке, а при клиентских
  > переходах, когда React перерисовывает layout со `<Script>` внутри. Проверка
  > тогда шла только по свежей загрузке, поэтому предупреждение не попалось.
  > Проверено на production-сборке (`next start`): там его нет вообще, это
  > предупреждение режима разработки. Архитектуру ради него не меняем.

- [x] 14.2 **Возврат на лендинг со страницы входа.** Ссылка «На сайт» со стрелкой в форме и логотип в левой панели, оба ведут на `/`. Ссылка в форме обязательна: на ≤900px левая панель скрыта и уйти со страницы было бы нечем
- [x] 14.3 **Выбор способа входа меняет поле ввода.** Правила вынесены в `lib/auth-providers.ts`:
  - Телефон и WhatsApp — номер `+992`, маска «00 000 00 00», `type="tel"`, кнопка «Получить код»
  - Google — адрес почты, `type="email"`, кнопка «Продолжить»
  - Telegram — имя пользователя с префиксом `@`, ввод чистится от посторонних символов, кнопка «Продолжить»
- [x] 14.4 Выбранный способ подсвечивается, повторный клик возвращает вход по телефону; `aria-pressed` на кнопках
- [x] 14.5 Подзаголовок меняется вместе со способом: при соцсети он больше не обещает код на телефон
- [x] 14.6 Проверено кликами: у всех четырёх способов свои подпись, тип поля, подсказка и кнопка; ошибки валидации срабатывают отдельно для почты и ника; консоль чистая

- [x] 14.8 **Исправлено: смена языка сбрасывала тему.** У пользователя со светлой темой и тёмной системной настройкой переключение языка возвращало тёмную.

  Причина: смена локали в next-intl — клиентский переход. React перерисовывает
  корневой layout и **стирает атрибут `data-theme`**, выставленный инлайновым
  скриптом, а сам скрипт повторно не выполняется: он есть только в
  первоначальном HTML. Атрибут исчезал, оставалась системная настройка.

  Решение: компонент `ThemeSync` в layout возвращает `data-theme` из
  `localStorage`. Через `useLayoutEffect`, то есть до отрисовки кадра, поэтому
  тема не мигает.

  Проверено на dev и production: `light` держится через `/en`, `/tg`, `/ru`,
  переключатель темы после переходов работает, в production консоль чистая.

- [ ] 14.7 **Это по-прежнему только интерфейс.** В настоящем OAuth Google и Telegram уводят на свою страницу входа, а не спрашивают адрес у нас. Когда появится backend (10.8), поля Google и Telegram, скорее всего, заменит редирект

### Решения по скиллу

- Правило скилла «полный запрет тире (`—`)» **не применяется**: оно написано под английскую типографику, а в русском тире — обязательный знак препинания, и он есть в согласованном макете
- Правило «никаких фейковых интерфейсов из `div`» затрагивает заглушку мокапа в Hero (ждёт Б-3) и витрину аналитики на странице входа (она из согласованного макета)
