## Этап 15 — Телефоны

**Цель:** сайт нормально работает на телефоне, а не только выглядит уменьшенным.

### Как удалось проверить

Окно Chrome не сжимается ниже ~1500px, поэтому мобильные ширины раньше не
проверялись. Решение: страница открывается в `iframe` заданной ширины —
внутри него медиазапросы считаются по ширине рамки, то есть верстка ведёт
себя как на телефоне.

Важный урок: проверять по `document.scrollWidth` **нельзя**. Добавленный
`overflow-x: clip` скрывает горизонтальный скролл, и сломанная вёрстка
выглядит целой. Правильная проверка — обходить элементы и сравнивать их
`getBoundingClientRect().right` с шириной вьюпорта, пропуская то, что уже
обрезано родителем с `overflow: hidden`.

### Найденные ошибки

- [x] 15.1 **Классы Tailwind конфликтовали, и `hidden` не работал.** У кнопки
      «Начать» стояло `hidden tablet:inline-flex`, но она была видна всегда:
      компонент `Button` подмешивает `inline-flex`, а в CSS Tailwind это
      правило идёт **после** `hidden`. Порядок классов в атрибуте роли не
      играет. Кнопка распирала шапку и давала горизонтальный скролл на всех

          конфликтующих утилит проект не генерирует. Это оказалось неверно.

  - [x] 17.7.1 Приём поставки — с причиной `PURCHASE`, единственная операция, где остаток растёт из ниоткуда
- [x] 17.8 Золото связано с `/reports/size-analysis`: размер считается ходовым, если на него приходится хотя бы пятая часть продаж лидера. Если отчёт не пришёл, золота просто нет — подсветка без данных врала бы
- [x] 17.13 **Новый товар — сеткой, а не по одному варианту.** Старая форма (`components/inventory/add-product-form.tsx`, Этап 16) заводила ровно один вариант: ни размеров, ни цветов, то есть кривую рисовать было не из чего.

Старый компонент `components/inventory/add-product-form.tsx` удалён, а не оставлен рядом: два способа завести товар разошлись бы при первой же правке

- [ ] 17.12 Ни один экран Этапа 17 не проверен в браузере с живыми товарами — в базе их пока нет. Проверены только сборка, типы и то, что страница отдаёт 200
